# Todo API (TypeScript)

A small REST API for managing todo items, built with **Express**, **TypeScript**, **Knex**, and **SQLite**. This project was built as a hands-on exercise to learn and practice TypeScript in a real Node/Express backend context — not a production application.

---

## 🇬🇧 English

### Purpose

This project exists purely as a **TypeScript practice project**. The goal was not to build a production-ready API, but to get hands-on experience with:

- Setting up a TypeScript + Node/Express project from scratch (`tsconfig.json`, `tsx` watch mode, `@types/*` packages)
- Typing Express request/response objects (`Request`, `Response`, `RequestHandler` generics)
- Working with `async/await` and understanding `Promise<T>` return types
- Designing a single source of truth for a data shape (a shared `Todo` interface) and deriving smaller types from it using TypeScript utility types (`Pick`, `Partial`, union types)
- Using Knex as a query builder with SQLite, including its migration and seed systems
- Debugging a real-world typo bug in a database migration (`timestamp` vs `timestamps`) and understanding how to safely fix and re-run migrations

### Data Model

The core entity is a `Todo`, defined once in `data/types.ts` and reused everywhere else in the codebase:

```typescript
export interface Todo {
  id: number;
  title: string;
  completed: boolean;
  created_at: string;
  updated_at: string;
}
```

Instead of repeating this shape across the model and controller layers, smaller, purpose-specific types are **derived** from it using TypeScript utility types:

- `Pick<Todo, "title">` — the shape needed to create a new todo (only a title is required; the rest is generated by the database)
- `Partial<Pick<Todo, "title" | "completed">>` — the shape needed to update a todo (any subset of title/completed can be sent)
  This keeps the whole codebase consistent: if the `Todo` shape ever changes, every derived type updates automatically.

### API Endpoints

| Method | Endpoint     | Description             |
| ------ | ------------ | ----------------------- |
| GET    | `/health`    | Health check            |
| GET    | `/todos`     | Get all todos           |
| GET    | `/todos/:id` | Get a single todo by id |
| POST   | `/todos`     | Create a new todo       |
| PUT    | `/todos/:id` | Update an existing todo |
| DELETE | `/todos/:id` | Delete a todo           |

### What Was Learned

This project intentionally moved from isolated TypeScript exercises into a real, database-backed application, in order to reinforce concepts like async error handling, Express generics, and derived types by applying them to a real bug (a migration typo) and a real refactor (centralizing a shared interface) — rather than learning them in the abstract.

### Veri Modeli

Projenin merkezindeki varlık `Todo`'dur; `data/types.ts` içinde bir kez tanımlanır ve kod tabanının geri kalanında tekrar tekrar kullanılır:

```typescript
export interface Todo {
  id: number;
  title: string;
  completed: boolean;
  created_at: string;
  updated_at: string;
}
```

Bu şekli model ve controller katmanlarında tekrar tekrar yazmak yerine, TypeScript'in hazır yardımcı tipleriyle ihtiyaca özel, daha küçük tipler **türetilir**:

- `Pick<Todo, "title">` — yeni bir todo oluşturmak için gereken şekil (sadece title zorunlu, geri kalanı veritabanı tarafından üretilir)
- `Partial<Pick<Todo, "title" | "completed">>` — bir todo'yu güncellemek için gereken şekil (title/completed'in herhangi bir alt kümesi gönderilebilir)
  Bu yaklaşım kod tabanını tutarlı tutar: `Todo` şekli bir gün değişirse, ondan türetilen tüm tipler otomatik olarak güncellenir.
